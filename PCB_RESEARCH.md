# Исследование формата PCB: `.lay6` (Sprint Layout 6)

Дата проверки: **2026-10-02**. Хост: Ubuntu 22.04. Команды приведены в §5 — результат можно
воспроизвести.

## 1. Решение (коротко)

**Платы не конвертируются, не проверяются автоматически и не редактируются агентом.** `pcb/`
находится вне зоны ответственности агента: запрет зафиксирован в `AGENTS.md` §2 и §8. Файл
`PCB_RESEARCH.md` — памятка для человека, объясняющая, почему так, чтобы решение не
пересматривали заново при каждом изменении.

## 2. Что за файл

`pcb/*.lay6` — настоящий бинарный контейнер, а не текст с нестандартным расширением:

```
$ file pcb/*.lay6
pcb/button_panel.lay6:    data
pcb/motor_control.lay6:   data
$ xxd pcb/motor_control.lay6 | head -1
00000000: 0633 aaff 0100 0000 07cf ebe0 f2e0 2031  .3............ 1
```

Признаки, по которым это проверено (скрипт — §5.1):

* одинаковая магическая последовательность `06 33 AA FF 01 00 00 00` в обоих файлах;
* доля печатаемых ASCII-байтов 13 % и 20 % — это шум псевдослучайных данных, а не текст;
* ни zlib, ни raw-deflate, ни gzip, ни bzip2, ни lzma не распаковывают файл ни с одного
  смещения в первых 64 байтах;
* осмысленных текстовых строк (длиной ≥ 4) внутри нет: найденные фрагменты вроде `UUUU` или
  `xXOK` встречаются в обоих файлах и являются частью данных.

Формат не документирован и проприетарен.

## 3. Существующие пути открыть или конвертировать

| Путь | Результат |
| --- | --- |
| Открытые парсеры `.lay6` | Не существуют. Поиск по GitHub, KiCad-форумам и профильным площадкам не дал ни одного рабочего парсера |
| Импорт через Sprint Layout 6.0 | Работает, но только на Windows и только вручную |
| EasyEDA Pro, ProtoboardDesigner, Diptrace | Импортируют `.lay6`, но это коммерческие сервисы; результат — производный файл чужого формата |
| **KiCad** | Есть импортёр, но **только в ветке разработки** — см. §3.1 |

### 3.1 Импортёр KiCad

В исходниках KiCad есть `pcbnew/pcb_io/sprint_layout/pcb_io_sprint_layout.{h,cpp}`; в заголовке
прямо сказано, что знание формата получено из проекта xlay. Проверено прямыми запросами к
GitLab — вот ответы по веткам:

```
$ for br in 10.0 9.0 master; do curl -s -o /dev/null -w "%{http_code}\n" \
    "https://gitlab.com/kicad/code/kicad/-/raw/$br/pcbnew/pcb_io/sprint_layout/pcb_io_sprint_layout.h"; done
404        # 10.0 — актуальный стабильный релиз
404        # 9.0
200        # master
```

То есть на 2026-10-02 открыть `.lay6` штатным релизом KiCad нельзя: нужна ночная сборка, у
которой нет гарантии стабильности, а результат импорта всё равно был бы производным, а не
исходным файлом. Это и стало решающим доводом против конвертации.

## 4. Что говорят специалисты про автоматические проверки PCB

Практика сообщества KiCad сводится к двум тезисам:

1. **DRC выполняют в редакторе перед экспортом.** Смысл проверки — поймать ошибку в момент, когда
   инженер ещё видит её на экране, а не спустя месяц в репозитории.
2. **CI-DRC оправдан там, где плата меняется постоянно и её правят несколько человек.** Он
   защищает от регрессий, внесённых обычным коммитом.

Для DomeControl ни то, ни другое не применимо: две платы, давно изготовленные, изменений
планируется мало. Автоматическая проверка зазоров и перекрытий на уже готовых платах не нашла бы
ничего, а проверка «после импорта в KiCad» отражала бы правила KiCad, а не те, по которым плата
рисовалась — то есть давала бы ложные срабатывания.

Что реально ценно для агентской разработки — это не DRC, а три вещи:

* плата читаема и диффабельна в git (сейчас — 143 КБ непрозрачного бинарника, который агент не
  может ни прочитать, ни отревьюить);
* ограничение габарита **120 × 80 мм** проверяется механически;
* имена цепей сверяются с пинами из `definitions.h` — это класс тихих багов «прошивка и плата
  разошлись», который сейчас не ловится ничем.

Все три требуют либо конвертации (запрещено §1), либо ручного экспорта Gerber из Windows. Обе
дороги дороже, чем устраняемый риск: платы работают, переделывать их не нужно.

## 5. Как перепроверить

### 5.1 Природа файла

```bash
file pcb/*.lay6
xxd pcb/motor_control.lay6 | head -1
python3 - <<'EOF'
import zlib, bz2, lzma
d = open("pcb/motor_control.lay6", "rb").read()
print("magic:", d[:8].hex())
for name, fn in (("zlib", zlib.decompress), ("gzip", lambda b: zlib.decompress(b, 47)),
                 ("bz2", bz2.decompress), ("lzma", lzma.decompress)):
    for off in range(64):
        try:
            fn(d[off:]); print(name, "сработал на смещении", off); break
        except Exception:
            pass
    else:
        print(name, "не распаковывается")
EOF
```

### 5.2 Наличие импортёра в KiCad

```bash
for br in 10.0 9.0 master; do
  printf '%s -> ' "$br"
  curl -s -o /dev/null -w '%{http_code}\n' \
    "https://gitlab.com/kicad/code/kicad/-/raw/$br/pcbnew/pcb_io/sprint_layout/pcb_io_sprint_layout.h"
done
```

Ожидается `404`, `404`, `200`. Если когда-нибудь первая строка станет `200`, импортёр попал в
релиз — и решение из §1 стоит пересмотреть, а не молча проигнорировать.

## 6. Что осталось за границей

Всё, что связано с электрической частью плат: разводка, силовые трассы, размеры площадок,
перекрёстные сценарии. Это проверяется на стенде и глазами, а не автоматически, и в объём
задач агента не входит.
