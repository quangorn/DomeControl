# План тестирования DomeControl

| Поле | Значение |
| --- | --- |
| Статус | Черновик плана, код ещё не изменён |
| Проверено против коммита | `04b801c` (`main`, 2021-04-24) |
| Дата | 2026-09-28 |
| Область | `firmware/` в приоритете, затем `ascom/` |
| Язык документа | Русский (код, идентификаторы и коммиты — английские) |

Документ описывает, какие тесты имеет смысл добавить в проект, в каком порядке и какими
средствами. Он опирается на фактическое состояние кода на указанном коммите, а не на желаемое.

---

## 1. Цель и объём

Сейчас в репозитории **нет ни одного теста**. Проверка прошивки сводится к сборке на Windows
(`-Werror` ловит часть ошибок) и к ручным прогонам через `ascom/DomeTest` и `Altair Dome Test.js`.
Ничего не защищает от регрессий в логике.

Цели по приоритету:

1. **Firmware** — логика протокола, движения, энкодера, концевиков, USART.
2. **Контракт firmware ↔ ASCOM** — строки команд и ответов, чтобы правило «четырёх точек» из
   `AGENTS.md` §5 перестало держаться на внимательности.
3. **ASCOM** — арифметика азимута и обёртки ответов (последний приоритет).

Вне объёма: `pcb/*.lay6` (бинарные файлы), установщик Inno Setup, аналоговая часть драйвера мотора.

## 3. Стратегия: уровни L0–L5 и один принцип

| Ур. | Что проверяется | Средства | Доступно сейчас |
| --- | --- | --- | --- |
| **L0** | Контракт протокола и соглашения из `AGENTS.md` §8 | Python, 0 зависимостей | да |
| **L1** | Логика модулей на тех же исходниках, но с подменёнными заголовками AVR | host `gcc` + fake AVR | да |
| **L2** | Главный цикл целиком: скриптованный USART-транскрипт | host `gcc` + fake AVR | да (после правки §11.1) |
| **L3** | **E2E: настоящая прошивка, настоящие регистры** | `avr-gcc` + `simavr` | нет, ставится |
| **L4** | Приёмка на железе после прошивки | `pyserial` + COM-порт | нет, стенд |
| **L5** | ASCOM-драйвер | xUnit + .NET | нет |

**Главный принцип, который нельзя терять из виду:**

> L1/L2 проверяют **намерение** (что мы записали в регистр), L3 проверяет **эффект** (что железо с этим
> сделало), L4 проверяет **железо** (что получилось на самом деле).

Зелёный `ctest` из L1/L2 **не является** доказательством работоспособности прошивки. Это защита от
регрессий логики. Этот тезис должен быть явно записан в `AGENTS.md` §3, когда появятся тесты.

## 4. L0 — контракт и соглашения

| Тест | Что проверяет |
| --- | --- |
| `tools/test_protocol_contract.py` | Парсит `const char* NAME = "VALUE";` из `firmware/source/common/definitions.c` и `public const string NAME = "VALUE";` из `ascom/ASCOM.Altair.Dome/Commands.cs` / `Responses.cs`. Требует идентичности множеств имён и значений. Автоматизирует правило «четырёх точек» (`AGENTS.md` §5) |
| то же, продолжение | Парсит таблицу команд из `AGENTS.md` §5 и требует совпадения с кодом. Документация перестаёт тихо устаревать |
| `tools/test_conventions.py` | grep-гарды по `AGENTS.md` §8: нет `sprintf`/`snprintf` в прошивке; нет `usartPrint*` до `sei()` в `main.c`; каждый модуль имеет парный `xxxInit()`, вызываемый из `main()` |

Ценность: нулевые зависимости, запускается где угодно, закрывает самый вероятный источник
рассинхронизации — протокол.

## 5. L1 — host-юнит-тесты модулей

### 5.1. Как подменяются регистры AVR

Модули **не трогают регистры напрямую** — это правило `AGENTS.md` §4 соблюдено: доступ идёт через
`OUTPORT`/`INPORT`/`DDRPORT` из `firmware/source/common/utils.h`, а номера портов и пинов лежат
только в `firmware/source/common/definitions.h`.

Цепочка раскрытия в `motorSetDirection()`:

```c
OUTPORT(MOTOR_DIR_PORT) |= (1 << MOTOR_DIR_PIN);   // как написано в motor.c
CONCAT(PORT, B)         |= (1 << 1);               // OUTPORT раскрылся, definitions.h дал B и 1
PORTB                   |= (1 << 1);               // CONCAT склеил имя
```

`PORTB` объявлен в `<avr/io.h>`. Если поставить свой `avr/io.h` **раньше** в пути поиска
(`-I firmware/test/fake`), то `#include <avr/io.h>` подхватит его (`-I`-каталоги ищутся и для
угловых скобок). На host-сборке регистры становятся обычными переменными в RAM:

```c
/* firmware/test/fake/avr/io.h — эскиз */
extern volatile uint8_t PORTB, PORTC, PORTD;
extern volatile uint8_t PINB,  PINC,  PIND;   /* тест пишет сюда: «нажал концевик» */
extern volatile uint8_t DDRB,  DDRC,  DDRD;

extern volatile uint8_t  TCCR1A, TCCR1B;
extern volatile uint16_t OCR1B;               /* «скорость» мотора */
#define WGM10 0
#define WGM11 1
#define COM1B1 5
#define CS00 0
#define CS02 2

extern volatile uint8_t MCUCR, GICR;
#define ISC00 0
#define ISC01 1
#define INT0  6

extern volatile uint8_t UBRRH, UBRRL, UCSRA, UCSRB, UCSRC, UDR;
#define U2X 1
#define TXEN 3
#define RXEN 4
#define RXCIE 7
#define TXCIE 6
#define URSEL 7
#define UCSZ0 1
#define UCSZ1 2
```

Дополнительно нужны три маленьких заголовка:

```c
/* fake/avr/interrupt.h */
#define ISR(vect) void vect(void)     /* ISR становится обычной функцией — тест зовёт её сам */
static inline void sei(void) {}
static inline void cli(void) {}

/* fake/util/atomic.h */
#define ATOMIC_BLOCK(x)               /* разворачивается в ничто: остаётся { ... } */
#define ATOMIC_FORCEON

/* fake/util/delay.h */
#define _delay_ms(x)  do {} while (0)
#define _delay_us(x)  do {} while (0)
```

**Компилируются те же самые `.c` файлы.** Никаких `#ifdef TEST` в продакшн-коде, никаких моков
модулей: наблюдаемость дают сами fake-регистры (`OCR1B` — скорость, бит `COM1B1` в `TCCR1A` — PWM
включён, бит 1 `PORTB` — реле направления) и перехваченный поток `UDR`.

Сборка:

```
gcc -std=gnu11 -Wall -Wextra -Werror -DF_CPU=12000000 \
    -funsigned-char -fpack-struct -fshort-enums -Wno-unknown-pragmas \
    -I firmware/test/fake -I firmware \
    firmware/test/test_motor.c firmware/source/motor/motor.c \
    firmware/source/encoder/encoder.c firmware/source/settings/settings.c \
    firmware/test/fake/fake_avr.c -o test_motor
```

Флаги намеренно повторяют AVR-сборку из `firmware/CMakeLists.txt`. Это не замена ей (предупреждения
`avr-gcc` и `gcc` различаются), но ловит сужения, знаковость и опечатки сразу, на Linux.

### 5.2. Полный инвентарь зависимостей от железа

| Идентификатор | Где используется |
| --- | --- |
| `PORTB`, `DDRB` | `motor.c` (шаг и направление), `led.c` |
| `PORTC`, `PINC` | `limits.c` (три концевика, активный низкий) |
| `PORTD`, `PIND` | `buttons.c` (две кнопки, активный низкий) |
| `TCCR1A`, `TCCR1B`, `OCR1B` + `WGM10/WGM11/CS00/CS02/COM1B1` | `motor.c` (Timer1, fast PWM, OC1B = PB2, предделитель 1024) |
| `MCUCR`, `GICR` + `ISC00/ISC01/INT0` | `encoder.c` (INT0 по фронту на PD2) |
| `UBRRH`, `UBRRL`, `UCSRA`, `UCSRB`, `UCSRC`, `UDR` + `U2X/TXEN/RXEN/RXCIE/TXCIE/URSEL/UCSZ0/UCSZ1` | `usart.c` |
| `sei`, `_delay_ms`, `ATOMIC_BLOCK` | `main.c`, `encoder.c`, `usart.c` |
| векторы `INT0_vect`, `USART_TXC_vect`, `USART_RXC_vect` | `encoder.c`, `usart.c` |

Порядка 25 идентификаторов. Fake-слой работает как **явный инвентарь связности прошивки с железом**:
если кто-то захардкодит регистр в обход `definitions.h`, host-сборка не скомпилируется.

### 5.3. Что fake-слой не эмулирует

| Что | На AVR | В fake | Следствие |
| --- | --- | --- | --- |
| `PORTB` | реальный вывод, ток, реле | переменная | проверяется намерение, не электрика |
| `PINB/PINC/PIND` | уровень с пина, подтяжка | тест пишет бит | нет дребезга, помех, тайминга подтяжки |
| `OCR1B` | аппаратный регистр, Timer1 формирует ШИМ на OC1B | переменная | рампа и остановка — да, скважность — нет |
| `TCCR1A/B` | режим и предделитель реально работают | переменная | проверяются выставленные биты, а не получившийся режим |
| `MCUCR/GICR` | INT0 реально ловит фронт | переменная | конфигурация — да, срабатывание — нет |
| `UDR` | запись **запускает** передачу | переменная | тест обязан сам «прокачивать» `USART_TXC_vect()` |
| `sei`, `_delay_ms` | прерывания и время | no-op | окно 40 мс и потери команд не воспроизводятся |
| `volatile` | реальная гонка ISR ↔ main | однопоточно | баг видимости §10.4 host-тестом **не поймать в принципе** |
| ширина `int`/`long` | 16/32 бита | 32/64 бита | `parseInt` за границей `int16_t` расходится; host-вывод не авторитетен |
| signed overflow | UB | UB, но gcc оптимизирует иначе | границы `int16_t` на хосте надёжно не проверяются |

Поэтому пункты про `parseInt` за границей `int16_t`, `volatile` и переполнение **выносятся в L3/L4**:
зелёный host-тест там был бы ложным успокоением.

### 5.4. Наборы тестов

**`test_utils.c`** — ядро диспетчеризации протокола

- `checkCommand`: точное совпадение; префикс с payload (`GT-42` матчит `GT`); не-совпадение; пустая
  строка; регистрозависимость; `GT` **не** матчит `XGT`.
- **Таблица диспетчеризации**: для каждой из 8 команд из `definitions.c` ровно одна ветка в `main.c`
  даёт свой эффект, и все 8 различимы. Автоматический детектор ловушки `AGENTS.md` §8.4.
- `parseInt`: `GT0`, `GT-42`, `GT+5`, `GT 5` (ведущий пробел), `GTabc` → 0, `GT12abc` → 12, `GT32767`,
  `GT-32768`.
- `printInt`: round-trip −32768…32767 в буфер 64 байта; максимальная длина 6+NUL — инвариант «влезает»
  заморожен.

**`test_encoder.c`**

- ISR при выключенном счёте → значение не меняется; включён вперёд → +1 на фронт; назад → −1.
- `encoderEnableCounting` задаёт направление, `encoderDisableCounting` останавливает.
- Границы: до 32766 / −32767 (переполнение — UB, фиксируется как ограничение, а не как поведение).

**`test_limits.c`** — самое неочевидное место прошивки

- Переход «не нажат → нажат» пере-якорит энкодер ровно один раз: forward → +100, reverse → −100,
  center → 0.
- Пока концевик **удерживается**, изменённое значение энкодера **не** пере-якорится. Это проверка
  фронтового, а не уровневого срабатывания — то, что позволяет энкодеру считать «сквозь» точку
  концевика во время движения.
- Отпустили и нажали снова → пере-якорь повторяется.
- Порядок в главном цикле: `limitsProceed()` после ISR → скачок к 100 и продолжение счёта от 100.

**`test_buttons.c`**

- Удержание даёт `true` только на переходе; повторное нажатие после отпускания — снова `true`; оба
  конца независимы.
- Активный низкий уровень: подтяжка выставлена (`PORTD` биты 3/4), нажатие = 0 на пине.

**`test_motor.c`** — самая большая поверхность

- Инициализация: целевая скорость = `motorStartSpeed` (15), `OCR1B` = 15, `motorIsMoving()` = false,
  `COM1B1` снят.
- `motorStart(FORWARD)`: цель = 128; первый `motorProceed()` включает PWM (`COM1B1`) и даёт шаг +2;
  рампа **точно** достигает 128 без перелёта; `motorIsMoving()` становится true только когда
  `OCR1B > 15`.
- Фиксация числа шагов: **57** вызовов `motorProceed()` до 128 при дефолтах — защищает скорость рампы
  от случайного изменения.
- `motorStop()`: спад по 5 за вызов, PWM снимается ровно при `OCR1B <= 15`, реле направления
  возвращается в FORWARD, счёт энкодера выключается.
- `motorIsMoving()` == `OCR1B > motorStartSpeed` — тест документирует отсутствие отдельного флага.
- Реверс на ходу: целевая скорость принудительно падает до стартовой, пока направление не совпадёт,
  затем снова разгон; реле (`PORTB` бит 1) **не** переключается, пока мотор движется;
  `encoderEnableCounting` пере-взводится с новым направлением. Фиксирует текущее тонкое поведение.
- `motorToggle`: старт → стоп → старт.
- `motorGoTo`: цель == текущая позиция → мотор не запускается; вперёд с клампом (`500` → `100`);
  назад (`−500` → `−100`); остановка ровно на `encoderValue >= target` / `<= target`; ветка подмены
  лимитов (`forwardLimitPosition = reverseLimitPosition = motorTargetPosition`) не даёт остановиться по
  концевику; реверс из движения в противоположную сторону.
- `motorFindCenter`: из позиции ≠ 0 едет и останавливается по `limitsIsOnCenter()`; из ровно 0 — не
  стартует и не зависает.
- **Инвариантный/fuzz-тест**: случайная последовательность команд + симулированный энкодер (1 шаг за
  `motorProceed()` в текущем направлении). Инварианты: `OCR1B ∈ [15, 128]`, позиция не выходит за
  `[−100, 100]`, любая последовательность завершается остановкой.

**`test_usart.c`** — кольцевой буфер и кадрирование

- `usartPrintln("OK")` → поток `O K \r \n`; `usartSendIsActive` поднимается и опускается после
  последнего TXC.
- Обёртка буфера: прогон > 64 байт через 64-байтный буфер с прокачкой TXC — точное совпадение
  байтового потока (проверка модульной арифметики).
- Зависание на полном буфере (`AGENTS.md` §8.5): запись 65 байт без прокачки не завершается. Тест
  писать как «нет прогресса после N вызовов ISR», иначе раннер повиснет.
- Кадрирование приёма: побайтно `G T - 4 2 #` → `usartGetReceivedCommand()` отдаёт `"GT-42"` ровно
  один раз, второй вызов — `NULL`.
- **Граница кадра** (§10.1): тело 62 байта работает, тело 63 байта возвращается пустой строкой.
- **Две команды в одном пакете** (`ST#GEV#`): вторая перезаписывает первую до чтения (§10.2).
- `USART_PRESCALER`: `F_CPU/8/BAUD − 1` для 12 МГц / 115200 / U2X == 12.

## 6. L2 — прогон главного цикла

Скриптованный транскрипт через fake-слой: подаём байты в `USART_RXC_vect`, прокачиваем
`USART_TXC_vect`, дёргаем пины `PINC`/`PIND`, сверяем **точную** последовательность ответов.

Сценарий: `GEV#` → значение; `GOF#` → `OK` + разгон; нажатие концевика → пере-якорь; `IM#` → 1;
`ST#` → `OK`; `IM#` → 0; мусорная команда → `Unrecognized command: …`. Плюс реплей всех строк
таблицы `AGENTS.md` §5 — исполняемая версия контракта.

Это ближайшее к приёмочному, что идёт на Linux обычным `gcc`. Требует правки §11.1.

## 7. L3 — E2E на эмуляторе AVR

### 7.1. Выбор: simavr

[simavr](https://github.com/buserror/simavr) — эмулятор AVR, который грузит ELF напрямую и
моделирует периферию. Из README проекта (проверено 2026-09-28):

- поддерживаемые ядра включают **ATMega8/16/32** — ровно наш MCU;
- эмулируются: *IO ports* (включая прерывания по пинам), *Timers* 8 и 16 бит (Normal, CTC и
  **Fast PWM**, плюс прерывание по переполнению), *UART* с TX/RX-прерываниями и режимом
  loopback/echo, *External Interrupts, INT0 и прочие*, EEPROM, watchdog, ADC;
- есть поддержка **gdb** и **VCD**-трассировки (Value Change Dump) с точностью до такта AVR;
- проект прямо позиционируется как средство для «test units on your shipping firmware… to prevent
  regressions».

Это ровно тот набор периферии, который использует наша прошивка: Timer1 + OC1B, INT0, три пина
концевиков, USART.

Пакеты Ubuntu: `simavr` 1.6 + `libsimavr-dev` 1.6, `gcc-avr` 5.4.0, `avr-libc` 2.0.0, `binutils-avr`,
`gdb-avr`, `libelf-dev` (для сборки из исходников), `gtkwave` (для просмотра трасс).

### 7.2. Готовые кирпичи в simavr

В репозитории simavr есть всё, что нужно, чтобы не писать эмуляцию железа с нуля:

| Кирпич | Что даёт нам |
| --- | --- |
| `examples/parts/uart_udp.c` | USART прошивки ↔ **UDP-сокет** (порт 4321). Python-тест говорит с прошивкой по сети |
| `examples/parts/uart_pty.c` | USART прошивки ↔ **pty** (`/dev/pts/N`). `pyserial` открывает его как обычный порт |
| `examples/parts/button.c` | генерация нажатия на пин через `avr_raise_irq`, с авто-отпусканием по таймеру тактов |
| `examples/parts/rotenc.c` | эмуляция поворотного энкодера — импульсы, аналогичные нашим INT0 |
| `simavr/sim/avr_ioport.h` | `AVR_IOCTL_IOPORT_GETIRQ('C')` + `IOPORT_IRQ_PIN0…7` — инжекция внешнего уровня пина; `AVR_IOCTL_IOPORT_GETSTATE` — чтение `PORT`/`DDR`/`PIN`; `AVR_IOCTL_IOPORT_SET_EXTERNAL` — значения по умолчанию для входов (подтяжки) |
| `tests/atmega88_uart_echo.c` + `tests/test_atmega88_uart_echo.c` | **шаблон харнесса и раннера**: 2.7 КБ и 335 байт. Копируем структуру |
| `tests/atmega88_timer16.c`, `tests/atmega48_ioport.c`, `tests/atmega168_ioport.c` | образцы работы с Timer1 и с инжекцией уровней на пины |
| `simavr/sim/sim_vcd_file.c` | VCD-трассы для проверки формы ШИМ |

`uart_pty` — ключевой кирпич: **один и тот же протокольный тест гоняется и на эмуляторе, и на
железе**, меняется только имя порта. Это делает L4 почти бесплатным продолжением L3.

### 7.3. Архитектура харнесса

```
        Python-тест (pytest)
          │            │
          │ UDP :4321  │ TCP :4322 (управляющий канал)
          ▼            ▼
   ┌──────────────────────────────────────────┐
   │ firmware/test/sim/harness.c              │
   │  • avr_make_mcu_by_name("atmega8")       │
   │  • avr_load_firmware(<DomeControl.elf>)  │
   │  • uart_udp / uart_pty  → USART          │
   │  • хук IRQ пина PORTB.2 (OC1B) → запись  │
   │    (avr->cycle, value) для анализа ШИМ   │
   │  • управляющий канал: set/pulse/state    │
   │  • avr_run() в цикле                     │
   └──────────────────────────────────────────┘
          │ avr_raise_irq(IOPORT_IRQ_PIN0+n)
          ▼
   концевики PC0/PC1/PC2, кнопки PD3/PD4, INT0 PD2
```

Управляющий канал (простой текстовый протокол, ~150 строк C) даёт тесту:

| Команда | Действие |
| --- | --- |
| `set C 0 0` | концевик forward нажат (`avr_raise_irq` на пин 0 порта C) |
| `set C 0 1` | концевик forward отпущен |
| `pulse D 2 40` | 40 импульсов на PD2 (INT0) с заданной длительностью — эмуляция энкодера |
| `state B` | вернуть `PORT`/`DDR`/`PIN` порта B (`AVR_IOCTL_IOPORT_GETSTATE`) |
| `cycles` | текущее `avr->cycle` — для проверок тайминга |
| `quit` | завершить эмуляцию |

VCD-трасса (`gtkwave`) — для ручного разбора; автотесты проверяют ШИМ по записанным переходам пина
OC1B (частота и скважность считаются из `(cycle, value)` в Python), чтобы не зависеть от внешнего
инструмента.

### 7.4. E2E-сценарии, которые имеет смысл покрыть

1. **Транскрипт протокола на настоящей прошивке.** Все 8 команд из таблицы `AGENTS.md` §5 →
   ожидаемые ответы, включая `Unrecognized command: …`. То же, что L2, но с реальными ISR и таймером.
2. **Фактический baud.** Проверка, что `USART_PRESCALER` для 12 МГц / 115200 / U2X даёт корректный
   `UBRR` = 12: подаём байты с хоста и убеждаемся, что прошивка их разбирает. Ловит ошибку в
   предделителе, которую host-тест видит только как число.
3. **Потеря команды из-за `_delay_ms(40)`** (TODO `AGENTS.md` §9). Отправить `ST#GEV#` одним пакетом
   и убедиться, что обрабатывается только одна команда. Это доказательство бага, а не предположение.
4. **Кадрирование на границе.** Тело 62, 63, 64 байта → пустой ответ / `Unrecognized command` /
   перезапись начала буфера. Подтверждает §10.1 на реальном железе.
5. **Рампа и ШИМ.** `GOF#` → OC1B (PB2) реально начинает переключаться; измеренная частота и
   скважность соответствуют Timer1 (fast PWM, предделитель 1024). **Здесь же проверяется вопрос из
   §10.9 про режим WGM11:10.**
6. **INT0 и энкодер.** `pulse D 2 40` при активном счёте → `GEV#` даёт +40; при выключенном счёте →
   без изменений; при `GOR#` → −40. Проверяет фронт INT0, а не только логику ISR.
7. **Концевики и пере-якорь.** Движение вперёд, `set C 0 0` → движение останавливается, `GEV#` = 100.
8. **`FC` (find center).** Из произвольной позиции `FC#` → `OK`, движение к центру, `set C 2 0` →
   остановка, `GEV#` = 0.
9. **`motorIsMoving` по времени.** `IM#` = 1 сразу после `GOF#`, затем 0 после `ST#` — с реальной
   рампой, а не пошагово.
10. **Границы `int16_t`.** `GT99999#` → поведение на AVR с 16-битным `int` (это то, что host-тест
    воспроизвести не может). Проверяет §10.3.

### 7.5. Альтернативы и почему не они

| Вариант | Вердикт |
| --- | --- |
| [QEMU](https://www.qemu.org/docs/master/system/target-avr.html) `qemu-system-avr` | **Не подходит.** Документация прямо говорит: поддерживаются «few Arduino boards», модель «limited to USART & 16-bit timer devices», машины — `mega2560` и подобные. Нет ATmega8, нет INT0, нет пинового GPIO. Нам нужны ровно те устройства, которых там нет |
| `simulavr` 1.0.0 (есть в apt) | Живой, но заметно старее и беднее по периферии; поддержка ATmega8 требует отдельной проверки. simavr выигрывает по покрытию и по готовым кирпичам (§7.2). Оставить как план Б |
| `avr8js` (TypeScript) | Только ATmega328P, другая периферия. Не наш MCU |
| Wokwi CLI | Ориентирован на ATmega328P/ATtiny и облачный запуск; ATmega8 нет |
| Proteus VSM, Atmel Studio simulator | Windows GUI, коммерческие/нескриптуемые, не годятся для CI |
| `avr-gdb` + `simavr -g` | Работает без написания C-харнесса, но инжекция прерываний и пинов через gdb медленная и хрупкая. Годится для отладки, не для автотестов |
| Только реальное железо | Не автоматизируется, не воспроизводится, не гоняется на каждый коммит |

### 7.6. Риски L3 и что подтвердить спайком

До написания полного харнесса сделать спайк на полдня:

1. Собрать прошивку `avr-gcc` из `firmware/CMakeLists.txt` с внешним toolchain-файлом.
2. Собрать харнесс по образцу `tests/atmega88_uart_echo.c`, подключив `uart_udp`.
3. Убедиться, что команда `GEV#` доходит и ответ приходит.
4. Подтвердить точный вызов для инжекции уровня на пин (`avr_raise_irq` + `AVR_IOCTL_IOPORT_GETIRQ`)
   и что он меняет `PINC` так, как ожидает `limitsIsForwardLimitReached()` (активный низкий уровень).
5. Подтвердить, что OC1B/PB2 действительно переключается и это видно на хуке пина.

Если пункт 4 или 5 не подтвердится — пересмотреть способ инжекции до написания тестов, а не после.

Дополнительно: пакет `simavr` в Ubuntu ставит только бинарник и библиотеки; примеры
`examples/parts/*` не устанавливаются. Значит либо собирать simavr из исходников (`make`,
нужен `libelf-dev`), либо вендорить нужные `uart_udp.c` / `uart_pty.c` / `button.c` в
`firmware/test/sim/parts/`. Лицензия проекта — **GPLv3** (`LICENSE`), лицензия simavr — тоже GPL,
так что вендоринг совместим; в заголовках файлов нужно сохранить copyright.

## 8. L4 — приёмка на железе

`tools/protocol_check.py` (на `pyserial`, уже установлен): полная матрица команд из
`AGENTS.md` §5 по реальному COM-порту на 115200, с проверкой таймаутов ответа, пути
`Unrecognized command`, некорректного ввода и поведения `GT` вне диапазона.

Двойная польза: смоук-тест после прошивки и исполняемая версия таблицы протокола. Благодаря
`uart_pty` (L3) этот же файл гоняется на эмуляторе — меняется только имя порта.

## 9. L5 — ASCOM-драйвер (низший приоритет)

- Юнит-тесты чистой математики: `AzimuthToEncoderValue` / `EncoderValueToAzimuth` — round-trip в
  пределах 0.533°/шаг, ветка «короткого пути» при delta > 180°, краевые 0/180/359.9, клампы ±100.
- Обёртки ответов: `SendCommandWithIntResp` на нечисловой ответ должен бросать;
  `SendCommandWithSimpleResp` на `Unrecognized command:` должен бросать.
- `ShutterStatus` (отражает только флаг в памяти — `AGENTS.md` §6) — зафиксировать как известное
  ограничение тестом-документацией.
- Требует выделения интерфейса транспорта в `Driver.cs` (см. §11.2) и наличия .NET.

Самое ценное долгосрочно: направить ASCOM-драйвер на `uart_pty` от simavr. Тогда «драйвер ↔
прошивка» тестируется целиком без железа.

## 10. Кандидаты в баги

Найдено **статическим чтением**, не выполнением. Каждый пункт нужно подтвердить тестом; ни один не
считается доказанным.

1. **`usart.c`: тело команды в 63 байта превращается в пустую строку.** При `#` на позиции 63
   `usartReceivePos` становится 0, и `buffer[0] = '\0'` затирает первый символ. Рабочая длина — 62,
   а не 64, как неявно следует из `AGENTS.md` §8.6.
2. **Две команды в одном пакете: первая теряется молча.** Очереди нет, буфер один. Вместе с
   `_delay_ms(40)` это реальный сценарий потери команды от драйвера.
3. **`parseInt`: сужение до `int16_t`.** `GT99999` даёт отрицательное значение → `GoTo` уезжает в
   обратную сторону. Конкретизирует ловушку `AGENTS.md` §8.7. Точное значение зависит от ширины
   `int`/`long` и должно проверяться на AVR (L3), а не на хосте.
4. **`usartReceiveBuffer` не `volatile`**, а пишется в ISR и читается в `main` — риск видимости
   данных. Host-тестами не обнаруживается в принципе (§5.3).
5. **Префиксное сравнение `checkCommand`.** Любая будущая команда, являющаяся префиксом другой, будет
   молча затенена. Тест диспетчеризации делает это красной сборкой, а не полевым багом.
6. **`printInt` без параметра размера** — инвариант «≥ 7 байт» держится только на вызывающих.
   Сегодня безопасно (буфер 64), тест замораживает инвариант.
7. **`motorStart()` не пере-взводит направление, если мотор уже движется.** Реле переключится только
   после спада рампы, а энкодер до этого считает в старом направлении. Тест покажет, задумано ли это.
8. **`motorFindCenter()` из позиции 0.** `motorGoTo()` выходит раньше, `motorGoToEnabled` остаётся
   false, а `motorFindingCenter` = true → `motorProceed()` вызывает `motorStop()` каждую итерацию.
   Безвредно, но должно быть зафиксировано.
9. **Режим Timer1 под вопросом.** Комментарий в `motor.c` говорит «fast PWM Mode», а выставлена пара
   `WGM11|WGM10` при `WGM12 = 0`. На ATmega8 таблица режимов Timer1 отличается от ATmega328: набор
   `WGM13:10 = 0011` и набор `0111` — это разные режимы (phase correct vs fast PWM, разрядность).
   Требует проверки по даташиту ATmega8 и подтверждения VCD-трассой в L3. **Host-тест этот вопрос
   даже не может поставить** — он видит только записанные биты.

## 11. Требуемые правки продакшн-кода

1. **`firmware/source/main.c`: вынести цепочку `if / else if` из `while (1)` в функцию**
   `static void processCommand(const char* cmd)`. Поведение не меняется, но диспетчеризацию (и L2)
   становится возможно вызвать без бесконечного цикла. Единственная обязательная правка в прошивке.
2. **`ascom/ASCOM.Altair.Dome/Driver.cs` (только для L5): выделить интерфейс транспорта**
   (`ISerialTransport`) — иначе юнит-тесты обёрток `SendCommandWith*Resp` невозможны без железа.
3. **Опционально для L3:** ничего. Трассы и инжекция делаются на стороне харнесса, прошивка
   остаётся нетронутой. Секция `_MMCU_` для VCD не требуется.

## 12. Структура файлов

```
firmware/test/
  CMakeLists.txt        # отдельная host-сборка: enable_testing() + add_test() на каждый набор
  runner.h              # мини-раннер: TEST_ASSERT_*, сводка, ненулевой exit code
  fake/
    avr/io.h            # регистры как переменные (см. §5.1)
    avr/interrupt.h     # ISR(...) → обычная функция, sei/cli — no-op
    util/atomic.h       # ATOMIC_BLOCK / ATOMIC_FORCEON → no-op
    util/delay.h        # _delay_ms / _delay_us → no-op
    fake_avr.c/.h       # fakeAvrReset(), setPin(), pumpTx(), feedRxByte()
  test_utils.c  test_encoder.c  test_limits.c  test_buttons.c
  test_motor.c  test_usart.c    test_main_loop.c
  sim/                  # L3
    harness.c           # atmega8 + uart_udp/pty + управляющий канал
    parts/              # при вендоринге: uart_udp.c, uart_pty.c, button.c (GPL, сохранить copyright)
    CMakeLists.txt      # сборка через avr-gcc + libsimavr
tools/
  test_protocol_contract.py   # L0
  test_conventions.py         # L0
  protocol_check.py           # L4 (и L3 через pty)
```

Два жёстких ограничения:

1. **Тесты нельзя класть в `firmware/source/`** — там `file(GLOB_RECURSE "source/*.c" "source/*.h")`
   (`firmware/CMakeLists.txt:15`), и тестовые `main()` вместе с подставным `avr/io.h` попадут в
   AVR-сборку и сломают линковку.
2. Host-сборку держать в `cmake-build-test/` — путь уже покрыт `.gitignore` (`cmake-build-*`).

## 14. Что не покрывается ничем из перечисленного
